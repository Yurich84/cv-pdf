# CV PDF

Генератор резюме: дані лежать у JSON, верстка — у Blade-шаблонах,
на виході — HTML для прев'ю в браузері та PDF через [dompdf](https://github.com/dompdf/dompdf).

Дві незалежні осі: **шаблон** (як виглядає) і **версія даних** (що написано).
Будь-яку версію можна віддати будь-яким шаблоном — під різні вакансії зручно
тримати різні JSON-и й перемикатися між ними, не чіпаючи верстку.
Портфоліо лежить окремо й спільне для всіх версій: проєкти під вакансію
не переписуються.

## Вимоги

- PHP 8.1+
- [Composer](https://getcomposer.org/)

## Встановлення

```bash
composer install
```

## Генерація PDF

```bash
php pdf.php                           # classic + default, файл у pdf/
php pdf.php modern                    # інший шаблон
php pdf.php --data=backend            # інша версія даних
php pdf.php modern --data=backend ~/Desktop/CV.pdf
php pdf.php --help                    # список шаблонів і версій
```

Аргументи розпізнаються за виглядом, а не за позицією: `*.pdf` — це шлях до
файлу, решта — шаблон. Версія даних іде прапорцем `--data=`, бо на вигляд не
відрізняється від імені шаблону.

Скрипт друкує шлях до створеного файлу. За замовчуванням це
`pdf/CV_<шаблон>_<дата>_<час>.pdf` (для не-типової версії —
`CV_<шаблон>_<версія>_<дата>_<час>.pdf`); тека `pdf/` у `.gitignore`.

## Прев'ю в браузері

```bash
php -S localhost:8000
```

- `http://localhost:8000/` — шаблон і версія за замовчуванням
- `http://localhost:8000/?template=modern` — конкретний шаблон
- `http://localhost:8000/?data=backend` — конкретна версія даних

Прев'ю рендериться тим самим кодом, що й PDF, тому правки видно без
перегенерації файлу. Верстка розрахована на dompdf, тож у браузері можливі
незначні розбіжності — фінальним вважається PDF.

## Шаблони

| Шаблон | Опис |
|---|---|
| `classic` (за замовчуванням) | Одна колонка на дві сторінки, ATS-friendly — коректно парситься роботами вакансійних сайтів. Без портфоліо: для ATS важлива стислість |
| `modern` | Дві колонки, фото, темна шапка, синя бічна смуга; портфоліо з картинками йде окремими сторінками на всю ширину, без смуги |

Список шаблонів — у `src/Template.php`. Ім'я шаблону приходить ззовні
(аргумент CLI або `?template=`), тому воно завжди звіряється з білим списком
і ніколи не підставляється у файловий шлях напряму.

## Де правити вміст

Резюме — у `data/<версія>.json`, портфоліо — окремо в
`data/shared/portfolio.json`.

Версія CV (`data/default.json`):

| Ключ | Що містить |
|---|---|
| `label` | Опис версії для `--help`; більше ніде не виводиться |
| `profile` | `name`, `title`, `photo`, `location`, `email`, `phone`, `summary` |
| `contacts` | Рядки сайдбару: `icon`, `text`, `url` |
| `socials` | Те саме плюс `label` — коротка назва для однорядкової шапки `classic` |
| `experience` | `role`, `company`, `location`, `from`, `to`, `summary`, `items[]` |
| `education` | `degree`, `school`, `location`, `from`, `to` |
| `languages` | `name`, `level` |
| `skills` | `top[]` — головний стек, `groups{}` — згруповані навички, `familiar[]` |

Портфоліо (`data/shared/portfolio.json`) — масив проєктів із ключами
`title`, `image`, `stack[]`, `text[]`. Файл один на всі версії, бо проєкти
не підлаштовуються під вакансію. Виводить його тільки `modern`; якщо файлу
немає, секція просто не рендериться.

Пропущені ключі підставляє `Cv.php` порожніми значеннями, тому шаблон не
впаде через недописане поле — але й не покаже те, чого в JSON немає.

`icon` має бути символом з DejaVu Sans (`☎ ✉ ✈ ⌂ ●`): емодзі та інші гліфи
dompdf малює порожнім прямокутником.

Зображення — у `src/resources/img/` (фото) та `src/resources/img/portfolio/`
(скриншоти проєктів). Вони вшиваються в документ як data URI, тому однаково
працюють і в браузері, і в dompdf.

## Версії даних

У репозиторії один набір — `data/default.json`, і саме його правлять під
конкретну вакансію. Якщо треба тримати кілька паралельно, версія — це просто
ще один файл у `data/`:

```bash
cp data/default.json data/backend.json   # далі правити під вакансію
php pdf.php --data=backend
```

Версіями вважаються файли верхнього рівня `data/*.json`; підтека `shared/`
у список не потрапляє. Реєструвати нову версію ніде не треба — список
збирається з теки. Ім'я, що приходить ззовні (`--data=` або `?data=`),
спершу шукається серед імен реальних файлів і тільки потім перетворюється
на шлях, тому підставити туди `../щось` не вийде.

Менше навичок у версії означає менше колонок у `classic`: `columns(4)` ріже
список на рівні частини, тож при короткому списку колонок може вийти менше
чотирьох, а задана їм ширина 25% лишиться.

## Як додати свій шаблон

1. Створити теку `src/view/templates/<name>/` з файлами `index.blade.php`
   та `styles.css`.
2. Додати `<name>` у `Template::AVAILABLE` (`src/Template.php`).
3. `php pdf.php <name>`

У шаблон передаються змінні: `$css`, `$profile`, `$photo`, `$summary`,
`$contacts`, `$socials`, `$experience`, `$education`, `$languages`,
`$portfolio` (усе — масиви з JSON) і `$skills` — об'єкт `Skills` з методами
`top()`, `groups()`, `familiar()`, `flat()` та `columns(n)`, де `n` це
побажання: остання колонка може бути неповною. Див. `src/Html.php`.

Якщо шаблону портфоліо не потрібне, достатньо не виводити `$portfolio`:
`classic` так і робить.

## Особливості верстки під dompdf

Кілька речей, на які варто зважати при правках CSS — всі вони перевірені
на реальному рендері:

- **Немає flexbox і grid.** Колонки — таблиці, `float` або абсолютне
  позиціонування.
- **Селектор `*` перебиває поля `@page`.** Якщо в CSS є `* { margin: 0 }`,
  сторінка друкується без полів незалежно від `@page`. Тому в `classic`
  скидання перелічує теги поіменно.
- **`@page` приймає і дво-значний `margin`.** `margin: 30pt 38pt` у
  `classic` застосовується по обох осях — перевірено на рендері
  з dompdf v2.0.3.
- **Висока таблиця не починається на сторінці, де вона не вміщається
  цілком** — dompdf переносить рядок на наступну сторінку. Тому в `modern`
  колонки зроблені не таблицею.
- **`position: fixed` повторюється на кожній сторінці PDF**, `absolute` —
  тільки на своїй. У `modern` шапка й сайдбар — absolute, тому вони є лише
  на першій сторінці.
- **Позиціоновані елементи завжди малюються поверх потоку** — z-index не
  рятує, тому під ними не має бути контенту.
- **`box-sizing: border-box` не застосовується** до абсолютів і комірок
  таблиці: реальна ширина = `width` + `padding`. Звідси «дивні» числа
  на кшталт `width: 156pt` при колонці 190pt.
- **Таблиця розтягується до правого краю сторінки** незалежно від свого
  `width` і від `padding-right` батька. Поле праворуч доводиться робити
  порожньою колонкою-відступом.
- **`page-break-inside: avoid` переносить блок цілком.** У `classic` це
  стоїть на записі досвіду, щоб один період роботи не розривався між
  сторінками. Зворотний бік — якщо блок не влазить у залишок сторінки,
  унизу лишається порожнє поле; запас над ним див. у коментарі до `.entry`.
- **`page_script` не відкладає колбек**, а одразу проходить наявними
  сторінками, тому викликати його можна тільки після `render()`.
- **Шрифт** — вбудований у dompdf DejaVu Sans: у нього є потрібні гліфи
  (`☎ ✉ ✈ ⌂ ●`). Інші шрифти треба підключати через `@font-face`.

## Ліва смуга в modern

Смуга не може бути `fixed`: тоді вона лізла б і на сторінки портфоліо.
Тому `Pdf.php` рендерить документ двічі — перший раз без портфоліо, щоб
дізнатися, скільки сторінок займає саме резюме, — а потім домальовує смугу
через `page_script` на сторінках з другої по останню сторінку резюме.
Першу сторінку фарбує сам сайдбар. Вміст до портфоліо в обох рендерах
однаковий, тому і розбиття на сторінки збігається.

У прев'ю в браузері смуги на «наступних сторінках» немає — там весь
документ один потік.

## Структура

```
index.php                     прев'ю в браузері
pdf.php                       генерація PDF
data/
  default.json                дані резюме (версія під вакансію)
  shared/portfolio.json       проєкти, спільні для всіх версій
src/
  Html.php                    рендер Blade + вшивання CSS і картинок
  Pdf.php                     dompdf
  Template.php                реєстр шаблонів
  Cv.php                      читання data/*.json і значення за замовчуванням
  Skills.php                  розкладки навичок для шаблонів
  resources/img/              фото та скриншоти проєктів
  view/templates/<name>/      index.blade.php + styles.css
  view/cache/                 скомпільовані Blade-шаблони (gitignored)
pdf/                          згенеровані PDF (gitignored)
```
